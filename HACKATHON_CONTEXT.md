This is the durable project brief for the current hackathon effort. Read it before planning, building, or preparing a submission.

## Official event snapshot - verified July 25, 2026

- Event: Dollar Vibe Club Live Hackathon.
- Start: July 26, 2026, 12:00 AM Bangkok (UTC+7), which is July 25, 2026, 7:00 PM Kampala (UTC+3).
- Build window: 12 hours. The product brief is secret until the live start.
- Capacity: 18 live competitor seats; spots are first come, first served once claimed.
- Format: Build live with screen share, microphone, and camera available for check-ins. Keep the stream live for the entire 12-hour sprint; being closed for more than 15 minutes means removal and loss of the seat.

## Build operating system

Apply the starter-kit's seven stages in this order:

1. Define the user journey, conversion goal, and success criteria from the revealed brief.
2. Load the approved high-quality design guidance rather than falling into generic AI defaults.
3. Verify on localhost in a browser throughout development, including responsive checks.
4. Establish a deliberate `design.md` token system: typography, colors, spacing, surfaces, and components. Use Phosphor icons by default.
5. Generate or source bespoke, context-relevant assets; keep generated assets in `public/assets/`.
6. Use visual references for hierarchy and composition, not as a substitute for an original brand system.
7. Polish micro-components and optimize animation performance before submission.

## Non-negotiable delivery checklist

- Build only after the official brief is revealed.
- Keep the live screen-share setup resilient: power, internet backup, browser profile, mic/camera, and stream permissions checked before start.
- Maintain local git checkpoints at meaningful milestones.
- Prioritize a complete, testable deployment over speculative features.
- Before submission: test primary user flow, mobile layout, empty/error/loading states, external links, and the public deployment in an incognito browser.
- Record the deployed URL, repository URL, credentials/test data if needed by judges, and a short demo script.
